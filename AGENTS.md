# AGENTS.md

Chrome/Edge (Manifest V3) extension: reads the transaction table on a supported bank page (Maybank2u for now) and adds new rows to BudgetBakers Wallet through its REST API. Built for the owner's own use and friends; others are welcome to use it. Repo: https://github.com/Atsukio/bank-to-wallet-sync (branch `main`).

## Layout
Plain ES modules, no bundler, **no runtime dependencies**, no build step: load the folder unpacked at `chrome://extensions`. `package.json` exists only for tests and release tooling (`"type": "module"`).

| File | Role |
| --- | --- |
| `manifest.json` | MV3. Side panel is `popup.html`. Service worker is a module. Host permissions: `*.maybank2u.com.my`, `rest.budgetbakers.com`. `commands._execute_action` = Alt+Shift+W. |
| `background.js` | Service worker. Per-tab side panel enable/disable and the "not supported" popup, driven by the `onlySupported` and `hideWhenAway` settings. Icon click and the shortcut call `sidePanel.open`. First install opens Settings. `openPanelOnActionClick` is deliberately `false`. |
| `sites.js` | `SUPPORTED_BANKS` and `isSupportedUrl`. The one place to add a bank (plus its host in `manifest.json`). Used by the worker, the panel and Settings. |
| `popup.html` / `popup.js` | The side panel: account picker, reading, review list, add, undo. The biggest file; read its section comments first. |
| `matching.js` | Pure helpers: `signature`, `matchRecords` (pairing bank rows with Wallet records), `carryOver` (keeps manual choices across refreshes), `matchTransferRule`. |
| `wallet.js` | Wallet API client and the pure category logic (`matchRule`, `categoryHistory`, `guessCategory`, `memoryKey`), settings defaults (`getSettings`, `BEHAVIOUR_DEFAULTS`), payload builders, create/update/delete. |
| `scanner.js` | `scanPage`, `detectAccount`, `diagnosePage`, `watchPage` are **injected into the bank page** via `chrome.scripting.executeScript` (all frames). They must stay self-contained (no imports, no outer-scope references). |
| `demo.js` | Synthetic transactions, accounts, categories, rules, history and transfer rule for the **Demo data** button. |
| `options.html` / `options.js` | Settings: token, default account, currency, four switches, transfer-rule editor, remembered-choice counters, getting-started card, supported banks. |
| `unsupported.html` / `.js` | Popup shown when the icon is clicked where the panel is not allowed; has a cog to Settings (extension pages allow no inline scripts, hence the `.js`). |
| `style.css` | Material Design 3 tokens (generated block) and shared components. Used by every page. |
| `fonts/` | Bundled Roboto (variable weight, Latin) with its Apache 2.0 licence and NOTICE. Must stay in the zip. |
| `store/` | Chrome Web Store listing text and images (generated by `npm run screenshots`). |
| `tests/` | `npm test`: logic, scanner, background, panel, pages and build tests. `helpers.mjs` has the browser/Wallet stub. |
| `tools/` | `build.cjs` (zip), `palette.cjs` (M3 colours), `screenshots.mjs` (store images). |
| `.github/workflows/ci.yml` | Runs `npm test` and `npm run build` on every push and PR. |
| `PRIVACY.md` | Privacy policy (its URL goes in the Web Store dashboard). Keep it true to what the code does. |
| `dist/` | Built upload zip (the one place `.zip` is not gitignored). |

## Commands
```
npm install            # tooling only
npm test               # everything below; `npm test -- panel` runs files whose name contains "panel"
npm run build          # dist/bank-to-wallet-sync-<manifest version>.zip, verified (add -- --clean to drop older zips)
npm run screenshots    # store/*.png from the demo data
npm run palette -- "#1a73e8" --write
```
Browser for tests: Edge/Chrome are found automatically on Windows, macOS and Linux; set `CHROME_PATH` otherwise. Chrome 137+ ignores `--load-extension`, so tests run the real pages over HTTP against a stubbed `chrome` (see Testing).

## Design system (Material Design 3)
- Colours are M3 roles in the generated block of `style.css`, from `tools/palette.cjs` (Google's official algorithm; `npm i` installs `@material/material-color-utilities@0.3.0`, newer versions break under Node ESM). Current scheme: **Vibrant, seed `#1a73e8`**. The owner found the earlier muted teal dull. Never hand-edit the block; pages use `--md-*` tokens, never hex values. `--credit` (income green) and `--warn` (amber) are generated too. The extension icon is still the original teal pixel art.
- Where colour is used: primary for the title, links and filled buttons; secondary for dates and the balance; tertiary for categories and transfers; error for debits and sign/type warnings; chips: `.chip.in` (secondary container) "In Wallet", `.chip.likely` (tertiary container) "Likely in Wallet" and "Transfer", `.chip.check` (error container) "Type differs".
- Typography: M3 type scale in Roboto (bundled; a remote font would leak IPs and contradict `PRIVACY.md`). Base body-large 16/24 +0.5; body-medium 14/20 for secondary lines; label-large 14/20 500 for buttons; label-medium 12/20 500 for chips; title-large 22/28 for headings; headline-medium 28/36 for the Settings title. The owner found a 14px base too small: do not shrink it again.
- Components: pill buttons (outlined; `.primary` filled; `button.text` borderless; `button.icon-btn` round), 4px outlined text fields, compact M3 switches (40x24; the owner found 52x32 too big), collapsible `<details>` descriptions beside each switch, M3 two-line list items in the review list, an M3 divider in the unsupported popup.
- Check every UI change in light and dark. `npm run screenshots` renders the real pages.

## How things work

**Reading the page** (`popup.js` `readPage`)
- Auto-read: the panel reads the active supported tab when it opens and re-reads (debounced 100 ms) on a `b2w-page-changed` message, `tabs.onUpdated` for the active tab and `tabs.onActivated`. `watchPage()` (MutationObserver, 250 ms debounce, ping only) is injected on every read because the site changes its table without navigating. Chrome cannot open a side panel without a click, so the panel never opens by itself.
- `auto` reads are gated by the `autoRead` setting and skip when `busy`, in demo mode or without a token; `quiet` reads refresh in place (after an account change, ignore, undo); `force` re-checks Wallet even if the bank rows are unchanged. Switching back to a tab or focusing the panel forces a Wallet check. Manual button reads always run.
- `carryOver` keeps what the user did by hand (ticks, flipped signs, transfer choice, manual category) across re-reads, keyed by `signature` (date|desc|amount as read).
- `collectPages`: rows from earlier pages are merged into the list until **Clear list**.

**Amount signs** (`scanner.js`): a wrong sign adds an expense as income, so it is checked three ways.
1. `parseAmount` reads the cell text (leading/trailing minus incl. Unicode minus, brackets, DR/DB/DEBIT).
2. If the text has no sign, `visualSign` reads the cell's CSS: a minus drawn by `::before`/`::after`, or red/green text. Maybank2u draws debits in red with the minus in CSS, so text alone read them as positive.
3. `reconcileSigns` overrides using the Balance column when there is one (balance movement between neighbouring rows is the truth). Rows it can't verify are flagged `unsure` only if the text proved wrong elsewhere on the page; the panel leaves them unticked with a Flip sign button.

**Which Wallet account** (`popup.js` accounts section)
- `detectAccount()` (best-effort, **never verified on the real page**) returns `{label, digits}` from headings, an account drop-down or account/card-classed elements. `bankKey` = `d:<last4>` else `l:<normalised label>`. `settings.accountMap[key]` maps it to a Wallet account; else the default `settings.accountId`; else the panel asks (`resolveAccount`, Add disabled). Choosing in the picker saves the mapping (or the default if no bank account was detected). The detected label is shown under the picker so it can be checked, and **Compare** prints it (digits masked).
- Accounts come from `listAccounts` (active only), cached 10 min and stored as `accountList` for Settings.

**Matching against Wallet** (`matching.js` `matchRecords`)
- Nothing is written to Wallet to track syncs. Existing records for the date range are paired one-to-one, three passes: exact description + same type → done; same type → likely; **opposite type → likely with `typeMismatch`** (shown as "Type differs", no Replace, so a wrongly signed record isn't hidden as "In Wallet"). Ignored rows take no part. `sameDescription` ignores case/punctuation and accepts an 8+ char truncated prefix. Records with `recordState: void` are ignored.
- The REST API serves its own synced copy of Wallet, so a record deleted in the app can keep showing for a while. `existingRecords` captures `X-Sync-In-Progress` and `X-Last-Data-Change-At`; the coverage line shows them. **Compare** lists each Wallet record's source, state and updatedAt.

**Categories** (a record with none shows as "Unknown expense")
- Order: remembered manual choice (`categoryMemory`, keyed by `memoryKey`) → Wallet rule (`GET /record-rules`, `matchRule`: substring, longest keyword, skips transfer rules and other accounts' rules) → `guessCategory` from `categoryHistory` (last ~6 months, any account, up to 1000 records; same description, else same merchant; same income/expense type; "Unknown" ignored; most common wins). The per-row **Change** picker uses `listCategories` (`GET /categories`, response key assumed to be `categories`, **unverified live**).
- Caches: rules 5 min, history 10 min, categories 30 min, accounts 10 min. Failures never block adding.

**Transfers** (`transferRules` in Settings, or "Make transfer" per row): the record is created with `transfer: { pairingMode: 'new', accountId }` (no category/labels); Wallet creates the mirror record, whose id comes back as `createdMirrorRecordId`. The other account's page then sees the mirror as "In Wallet". **Unverified live.**

**Undo**: after an add, `lastAdd = { groups: [[id, mirrorId?]], at }` is saved (15 min). Undo calls `DELETE /records` with `{ ids }` (max 10 per request; a transfer and its mirror must go in the same request, hence `chunkGroups`). **Unverified live**; demo mode pretends.

**Other**: ignore list (`ignored`, capped at 2000 signatures); toolbar badge = number of new rows (set while the panel is open); first install opens Settings (getting-started card until a token is saved); `commands._execute_action` shortcut fires the same `onClicked`; balance = `balance.currentBalance` of the selected account. The bank's own balance is not read. Bank description goes in `note` (255 max), `counterParty` is unset. Dates are Malaysia time (UTC+8); records are created at 12:00 +08:00. Old `[m2u:<hash>]` note tags are stripped when reading.

**Settings** (`chrome.storage.local`; defaults in `getSettings`): `onlySupported`, `hideWhenAway` (service worker), `autoRead`, `collectPages` (panel), plus `token`, `accountId`/`accountName`, `currency`, `accountMap`, `transferRules`, `categoryMemory`, `ignored`, `lastAdd`, `accountList`. Changes apply live through `storage.onChanged`. The Chrome semantics of "panel stays open across tabs" (global enabled + per-tab enabled with the same path) are inferred from the docs and **untested in a real browser**.

**Demo mode** never reads or writes real settings: its ignores and category choices are in memory only. It swaps in fake accounts, so it must always be leavable: a banner ("Exit demo"), the Demo button (which toggles) and the Read button all call `exitDemo`/`leaveDemo`, which restore the real accounts, clear the list and re-read the page.

## The real Maybank2u page (learned from screenshots)
- History table columns: Date, Description, Amount (no Balance column on the credit card view). Foreign-currency rows show a second line in the description cell.
- Debits show as red "- RM 1,234.56" but the minus is not in the cell text. The owner's account is a credit card, so its Wallet balance is negative. Card repayments appear as "SPAYLATER REPAYMENT…" rows.
- If a layout, sign or account problem appears on the real page, do not ask for real transaction data. Ask them to click **Compare**: it ends with how the page marks amounts (markup, colour, pseudo-element content) with every digit masked, plus the detected account label.

## Wallet API notes
- Spec: `curl -sL https://rest.budgetbakers.com/wallet/openapi`. Read it instead of guessing field names. Paths are under `/wallet/v1/api`.
- Premium only. 300 requests/hour. 409 = first data sync still running. 401/403 = bad token.
- Amount sign decides income vs expense (a transfer is a separate `transfer` field, not a third type). List responses use keys like `records`, `accounts`, `recordRules`; pagination via `nextOffset`. Account has `archived`. `POST /records` max 50 (we send 20), `PATCH` max 10, `DELETE` max 10 ids. Record `recordState` includes `void`.

## Conventions
- Match the existing style: small functions, short comments that explain why, no frameworks, no runtime dependencies.
- Bank and Wallet data in repo files, screenshots, tests or examples must be **synthetic** (`demo.js`, test fixtures). Never commit, paste or read real transactions, API tokens or `.env` files. The owner's token only ever lives in extension storage.
- Files use CRLF on disk. Patching with scripts: normalise `\r\n` first and write back the original style, or use the Edit tool. For regex-heavy edits write a script file (heredoc escaping mangles backslashes). The Write/Edit tools need the file read in the session first.
- Keep `PRIVACY.md` and `store/LISTING.md` in step with behaviour changes (what is read, stored, sent, and permissions).
- New runtime file? Add it to `FILES` in `tools/build.cjs` (the build fails if a shipped file refers to one that isn't listed, and a test checks the zip).

## Testing
`npm test` runs, in `tests/`: `logic` (pure functions), `scanner` (signs and account detection on synthetic tables), `background` (panel rules per setting, shortcut, first run), `panel` (the side panel end to end), `pages` (Settings and the unsupported popup), `build` (the zip). `helpers.mjs` provides `newPanel(browser, server, env, file)`: it serves the repo over HTTP, injects a stub `window.chrome` and a fake Wallet `fetch` driven by `env` (tab URL, rows, detected bank, accounts, records, rules, categories, response headers), and exposes `window.__t` (call logs: created/deleted/patched records, badge text, scans) and `window.__fire(name, …)` to trigger `message`/`updated`/`activated`/`storage` listeners. A missing stub makes `popup.js` throw at load and the panel renders blank, so when adding a new `chrome.*` call to the panel, add it to the stub too.

Not coverable headless, so verify in a real browser when touching them: the service worker and side-panel enable/disable, the in-page watcher on real pagination, `detectAccount` on the real page, and the live Wallet calls for transfers, delete and categories.

## Releasing to the Web Store
1. Bump `version` in `manifest.json` (the store rejects a re-upload with the same version).
2. `npm test`, then `npm run build -- --clean`. The zip is written and verified by `tools/build.cjs`. **Do not build zips with `tar`**: Git for Windows' GNU `tar -a -cf x.zip` silently writes a plain tar archive, which the store rejects (the committed 0.1.0 and 0.1.1 zips were affected).
3. Update `store/LISTING.md` and `PRIVACY.md` if permissions or behaviour changed (the store's data-usage answers must match). `npm run screenshots` after visible UI changes.
4. Upload `dist/bank-to-wallet-sync-<version>.zip`.

## Commit messages
All commits follow [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/):

```text
<type>(<optional scope>)<optional !>: <imperative summary, lower case, no full stop>

<optional body: what changed and why, wrapped at 72 columns>

<optional footers: BREAKING CHANGE: ..., Co-Authored-By: ...>
```

- **Types:** `feat` (user-visible feature), `fix` (bug fix), `docs`, `refactor`, `test`, `ci`, `build`, `chore`, `perf`, `style`, `revert`.
- **Scope** is optional: `panel`, `scanner`, `matching`, `wallet`, `settings`, `background`, `sites`, `store`, `theme`. For example, `fix(scanner): read the sign from the debit column`.
- **Breaking changes:** put `!` after the type/scope and add a `BREAKING CHANGE:` footer that explains how to migrate (for example, stored settings that are reset).
- **Versioning:** the commits since the last release decide the next `manifest.json` version. Any breaking change means a major bump, otherwise any `feat` means minor, otherwise any `fix` means patch. `docs`, `ci`, `chore` and similar commits on their own don't need a release. A release commit is `chore(release): vX.Y.Z`.
- Commits made by an AI agent end with its `Co-Authored-By` trailer as the last footer.
- Commits before 2026-10-14 predate this rule. Don't rewrite history to fix them.
